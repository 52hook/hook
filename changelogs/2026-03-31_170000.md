# MPC 求解效率优化

**日期**: 2026-03-31
**修改概述**: 四项优化措施提升 MPC 求解效率，预计从 24-29ms 降至 10-15ms

---

## 修改详情

### 优化 1: GPR 预测双调用合并
**文件**: `scripts/env.py`
- **line 583-590 (行人预测)**: 将两次 `gpr.predict()` 合并为一次 `gpr.predict(obs_hist, return_std=True)`
- **line 654-660 (车辆预测)**: 同上
- **原值**: 两次独立调用（一次取均值，一次取方差）
- **新值**: 一次调用同时返回均值和方差
- **原因**: 每次 predict 需完整的 kernel matrix 计算，合并后省约 2-4ms/步

### 优化 2: IPOPT warm-start 参数开启
**文件**: `scripts/vehicle_obs.py`
- **line 1245-1254**: opts_setting 新增 warm-start 参数
- **原值**: `acceptable_tol=1e-8`, 无 warm-start
- **新值**: `acceptable_tol=1e-6`, `warm_start_init_point='yes'`, `warm_start_bound_push=1e-6`
- **原因**: IPOPT 之前忽略 solve_MPC 精心构造的热启动初值，开启后减少 3-8 次迭代

### 优化 3: B-spline 平滑器缓存
**文件**: `utils/global_bspline_smoother.py`
- **__init__**: 新增缓存变量 `_prev_path`, `_cache_smooth`, `_osqp_prob`
- **smooth()**: 添加路径变化检测（max_deviation < 0.5m → 跳过求解）和 OSQP workspace 复用
- **原值**: 每步重建 basis matrix + OSQP 从零求解
- **新值**: 路径不变时直接返回缓存，维度不变时复用 OSQP workspace
- **原因**: 参考路径在连续步间变化很小，避免不必要的重复计算

### 优化 4: 参数化 NLP 消除每步重编译（核心）
**文件**: `scripts/vehicle_obs.py` + `scripts/x_v2x_agent.py`
- **vehicle_obs.py**: 新增 `setup_parametric_nlp()`, `pack_apf_params()`, `solve_parametric()` 三个方法
  - 所有 APF 障碍物位置、车道线参数、红灯、TTC 均通过 CasADi 参数向量传入
  - OBCA 对偶变量预分配 4 个槽位（通过 lbx=ubx=0 控制激活/停用）
  - `ca.nlpsol()` 只在初始化时调用一次，后续只更新参数值
- **x_v2x_agent.py**: 
  - init 中调用 `setup_parametric_nlp()`
  - run_step 中替换 `solver_add_cost/soft_obs/bounds → solve_MPC` 为 `pack_apf_params → solve_parametric`
- **原值**: 每步重建 CasADi 符号图 + 调用 `ca.nlpsol()` 重新编译（~15-20ms 开销）
- **新值**: 编译一次（init 时），每步只做参数打包 + IPOPT 数值求解
- **原因**: CasADi NLP 编译（Jacobian/Hessian 符号微分）是最大性能瓶颈

## 验证方式
1. 运行任意场景，对比求解时间（日志第13列）
2. 确认轨迹跟踪精度无显著退化（横向误差 < 0.5m）
3. 确认 `ca.nlpsol` 只在 init 时打印编译信息

## 关联场景
所有场景（unsig_crossroad, roundabout, multilaneACC, mixed_traffic）
