# OBCA E+A+G 修复 Step 6 (G2): dual warm-start 按 actor.id 命中

## 修改概述

旧版 `_lam_cache / _mu_cache / _s_cache` 是 flat 张量, 命中条件为
`(horizon+1, tuple(edges_per_obs))` shape signature。一旦 OBCA slot
顺序变化 (一辆车驶离, 另一辆补位), cache 张冠李戴 -> warm-start 喂
错车的 dual, IPOPT 反而要从更糟的起点收敛。

档 2 (G2): 引入 `_dual_cache_by_id: dict[actor.id] -> (lam, mu, s)`,
每一拍按当前 `obs_actor_ids` 顺序拼回 flat cache; 缺失或 edge_count
不一致的 slot 用 0 兜底。FIFO 上限 64 防长仿真累积内存。

## 修改详情

### 文件: scripts/vehicle_obs.py

1. **`enable_dual_collision`** (line ~823)
   - 旧: shape sig 命中失败 -> 三个 cache 置 None
   - 新:
     ```python
     if not hasattr(self, "_dual_cache_by_id"):
         self._dual_cache_by_id = {}
     self._rebuild_flat_dual_from_dict()
     ```
   - shape_sig 仍保留, 仅作调试/对照 (不再用于 invalidate)

2. **新方法 `_rebuild_flat_dual_from_dict`** (Step 6 helpers 块)
   - 按 `obs_actor_ids` 顺序从 dict 取 `(lam_m, mu_m, s_m)` 拼出
     `(N+1, sum E)` / `(N+1, 4M)` / `(N+1, M)` 张量
   - 形状校验 `(N1, E)` / `(N1, 4)` / `(N1,)` 必须严格一致, 否则 0 兜底
   - 写回 `self._lam_cache / self._mu_cache / self._s_cache`

3. **新方法 `_writeback_dual_to_dict`**
   - 求解后从 flat 解切出 per-actor 张量, 按 `damping/0` 处理后写回
     dict, key = `int(aid)` (跳过 -1 占位)
   - FIFO 上限 `PM_DUAL_CACHE_MAX = 64`, 超出时保留最新一半

4. **`solve_MPC` 第 7 步** (line ~1638)
   - 在原先写 flat cache 的位置后追加:
     ```python
     try:
         self._writeback_dual_to_dict(lam_vec, mu_vec, s_vec)
     except Exception as e:
         logger.warning(...)
     ```
   - 异常路径不影响 flat cache 主路径, 只是损失下一拍的 dict 命中

5. **`disable_dual_collision` 不动 dict**
   - 仅清 flat cache (旧行为) — 短暂离开 OBCA 范围的 actor 再次进入时
     可保留 warm-start

## 修改原因

档 2 (G2) Slot reorder 是城市路口最常见的现象 (前车驶过, 后车补位)。
原版 cache 命中靠 shape signature -> 只要数量一致就用, 物理上对应
完全不同的车; warm-start 反而拖慢收敛。

按 actor.id 命中是 OBCA-MPC 文献 (TDR-OBCA / OCEAN-ADMM) 通用做法,
MPC 时间序列连续性沿物理对象走, 而非沿矩阵 slot 走。

## 验证结果

- `python -c "ast.parse(...)"` 通过, 无语法错误。
- 旧路径行为兼容: 当 `obs_actor_ids` 全为 -1 (未传 actor_ids 的旧
  调用), `_rebuild_flat_dual_from_dict` 全部 slot 走 `aid<0` 跳过,
  flat cache 全 0 -> 等价冷启动 (旧 shape mismatch 时也是 0)。
- 边数变化兜底: shape check 不一致 -> 0 兜底, 不抛异常。
- FIFO prune 在 65 个不同 actor.id 后触发 -> 跑 60 seed 路径前不会触发。
- Step 7 统一 smoke + 单场景 + 60 seed 回归; 期望 IPOPT 平均迭代次数
  不增加 (cache 命中率提升), MPC 时间不增加, 收敛失败次数下降。

## 关联场景

- A 路径硬伤的 part-3 修复; 与 Step 4/5 配合, 让 dual 解的 mass
  跟着物理车走。
- 高密度场景 (`mixed_traffic`, `unsig_crossroad`): slot reorder 频繁,
  受益最明显。

## 备注

- actor.id 在 CARLA 内同一个 World 实例内唯一, 但 World 重置后会复用。
  本 step 不在 disable 时清 dict, 假设场景脚本本身会 destroy & recreate
  Vehicle 对象 -> 新 id; 若用户跑长链路 reset 而 dict 复用, 可能出现
  shape mismatch -> 0 兜底, 不会崩, 只是损失 warm-start。
- `_dual_cache_by_id` 没有 actor type / bbox extent 校验, 同一 id 换
  车型时 lam_m shape mismatch 即兜底; 风险可控。
- 完整 E+A+G 修复链至此完成 (Steps 1-6); Step 7 做集成验证。
