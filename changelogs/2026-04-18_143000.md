# 2026-04-18 14:30:00 修复 extract_metrics.py 文件名解析 bug

## 修改概述
`extract_metrics.py` 的 `parse_filename()` 原正则 `^(.+?)_(.+?)_r(\d+)$` 对多下划线方法名（如 `GRIPC_noBSP_unsig_crossroad_r1`）错解析为 `method=GRIPC, scenario=noBSP_unsig_crossroad`，导致 `--batch --summary` 下消融方法（`GRIPC_noOBCA`/`noIGPR`/`noBSP`/`noQP`）全部被错误聚合到 `method=GRIPC`，汇总表缺失消融行。

## 修改详情
### 文件：`extract_metrics.py`
- **位置**：第 177-205 行 `parse_filename()`
- **原值**：单正则懒匹配，对多下划线方法名有歧义
- **新值**：新增 `KNOWN_METHODS` / `KNOWN_SCENARIOS` 白名单，先用 `_r\d+$` 剥离 repeat，再按 `KNOWN_METHODS` 前缀匹配，剩余部分作为 scenario。顺序上 `GRIPC_noXXX` 必须放在 `GRIPC` 之前以避免前缀吞食。

## 修改原因
不改这个 bug 就无法生成正确的消融实验汇总表，所有消融数据被吞到 `GRIPC` 行。

## 验证结果
```
GRIPC_noBSP_unsig_crossroad_r1.txt -> ('GRIPC_noBSP', 'unsig_crossroad', 1)
GRIPC_noBSP_roundabout_r12.txt     -> ('GRIPC_noBSP', 'roundabout', 12)
GRIPC_noIGPR_multilaneACC_r4.txt   -> ('GRIPC_noIGPR', 'multilaneACC', 4)
GRIPC_noOBCA_mixed_traffic_r40.txt -> ('GRIPC_noOBCA', 'mixed_traffic', 40)
GRIPC_noQP_unsig_crossroad_r29.txt -> ('GRIPC_noQP', 'unsig_crossroad', 29)
GRIPC_unsig_crossroad_r1.txt       -> ('GRIPC', 'unsig_crossroad', 1)
UDMC_roundabout_r1.txt             -> ('UDMC', 'roundabout', 1)
FSM_mixed_traffic_r2.txt           -> ('FSM', 'mixed_traffic', 2)
```
8 个典型文件名全部正确。`--batch --summary` 现在输出 7 方法 × 4 场景 = 28 行齐全。

## 关联场景
全部实验场景（unsig_crossroad / roundabout / multilaneACC / mixed_traffic）。
